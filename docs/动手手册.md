# 动手手册：从零到把 Harness 跑在鸿蒙手机上

> 本文是**唯一需要读的操作文档**：按顺序执行即可复现整个项目。
> 每一步都标注了**为什么**与**踩过的坑**；所有命令都在本机实测过。
>
> 结论先行：**不需要为鸿蒙编译任何原生模块**（实测，见《参考实现-构建要点》第八章）。
> 原生工作量集中在**一个宿主壳**（`libnode_ctl.so`，已写好并编译通过）与**打包**。

## 2. 生成"鸿蒙版清单"（裁剪 + 决定启动参数）

```powershell
node tools/make-prune-plan.mjs            _extract/desktop-runtime.json dist
node tools/make-ohos-runtime-manifest.mjs _extract/desktop-runtime.json dist
```
- `dist/prune-plan.json`：三档分类（KEEP / REVIEW / DROP）明细
- `dist/ohos-runtime.json`：**鸿蒙版运行包清单**（platform=openharmony/arm64）
- `dist/ohos-overlay/`：需要覆盖的文件（`node-addon-require-builtin` 的**纯 JS 桩**）

实测：`KEEP 11419 文件 / 106.4 MB`，`DROP 1072 文件 / 237.7 MB`（LibreOffice-win 182 MB 等）

## 3. 组装 M2 载荷

```powershell
node tools/assemble-resfile.mjs $asar dist/ohos-runtime.json `
     harmony/entry/src/main/resources/resfile/dsh --overlay dist/ohos-overlay
```
实测：**11419 个文件 / 106.4 MB，19 秒**，7 项校验全通过（含"**无二进制混入**"）。

同时生成 `resfile/launch.json` —— 里面固化了：
```json
{ "scriptRelative": "node_modules/@deepseek-ai/dsh/lib/bin.js",
  "args": ["web"],
  "hostArgv": ["--expose-internals","--jitless","--no-verify-heap"],
  "env": { "UV_USE_IO_URING": "0", "NODE_ENV": "production" } }
```

> ⚠ **`--expose-internals` 不能省**：没有它，`internal/modules/*` 全部 `MODULE_NOT_FOUND`
> （实测 5/5 失败）；有了它 + JS 桩，DSH 那条代码路径实测可用（见第八章）。

## 4. 放入 Node 运行时

从 `electerm/ohos-node-shared` 的 release 下载 **`libnode-arm64.so`**（120.9 MB）→
放到 `harmony/entry/libs/arm64-v8a/libnode.so`。

```powershell
# 若已有该文件，用这条核对（必须是真共享库）
& "$ndk\llvm\bin\llvm-readelf.exe" -h harmony/entry/libs/arm64-v8a/libnode.so | Select-String 'Type|Machine'
& "$ndk\llvm\bin\llvm-readelf.exe" -l harmony/entry/libs/arm64-v8a/libnode.so | Select-String 'INTERP'   # 必须【空】
```
实测：`Type: DYN` · `Machine: AArch64` · **无 INTERP** · `SONAME=libnode.so.137` ·
`NEEDED: libc++_shared.so, libc.so`（与宿主壳同 ABI ✓）

> ⚠ **绝不能**用 `hqzing/ohos-node` 的 PIE 版本（`ET_DYN + PT_INTERP`）：
> 它被 `dlopen` 后会把 local-exec `%fs` TLS 别名到宿主 TLS 块 → V8 首次堆分配即崩。
> ⚠ 该文件**没有 `.codesign` 段**；若商用机报签名问题，用
> `toolchains\lib\binary-sign-tool.jar` 自签（**strip 之后**再签）。

## 5. 一键构建（native + ArkTS + HAP）

```powershell
# M1 小包（121 MB，先验证"Node 能跑"）
pwsh -File tools/build-m1.ps1 -SkipNative -WithoutDsh

# 完整包（229 MB，含 DSH 载荷）
pwsh -File tools/build-m1.ps1
```
脚本内含 6 步校验（环境 / native / libnode ELF / ohpm / hvigor / HAP 内容），缺项红字报错。

**它会替你避开的三个坑**（都实测踩过）：
1. ArkTS 侧 import 原生模块 → 必须在 `entry/oh-package.json5` 声明
   `"libnode_ctl.so": "file:./src/main/cpp/types/libnode_ctl"` **且跑一次 `ohpm install`**
   ✗ 缺它 → 模块被解析成 `any` → 编译报 `arkts-no-any-unknown`
2. native 产物必须落到 `entry/libs/<abi>/`（CMakeLists 里设了
   `CMAKE_LIBRARY_OUTPUT_DIRECTORY`）✗ 否则 HAP 里**没有 `libs/`**
3. `resfile` 里的 **点文件会被 hvigor 排除**（11419 → 11337，少 82 个，全是
   `.history/.github/.npmignore/.travis.yml` 之类）—— 核对时要**直接查 HAP**，别只看磁盘

## 6. 装到手机（**当前卡在这一步**）

需要**一个能签 `com.dsh.harmony` 的 Profile** ✗ —— 手上那套签名材料绑的是
`com.harness.mobile`，bundleName 不匹配，装不上。三选一：

| 方案 | 做法 |
|---|---|
| **A（推荐）** | AGC → 我的应用 → 新建/选择 `com.dsh.harmony` → 证书/Profile 管理 → 申请**指定设备发布 Profile**，把手机 UDID 加进去 → 用它的 `.p7b` 配 `signingConfigs.devicetest` |
| **B** | DevEco → File → Project Structure → Signing Configs → 勾 **Automatically generate signature**（登录华为账号，对已连接设备生成）|
| C ✗ | 临时把 bundleName 改成 `com.harness.mobile` 复用旧 Profile —— 会与已上架应用冲突，**不推荐** |

签好之后：
```powershell
hdc list targets
hdc install -r harmony/entry/build/default/outputs/default/entry-default-signed.hap
hdc shell aa start -a EntryAbility -b com.dsh.harmony
```
**预期**：应用启动 → 面板显示 `native state=running` → 探测到 HTTP → 出现
**"Node.js 已在鸿蒙上运行 ✓"** 页面（M1）/ DSH 界面（M2）。

排障第一站永远是：`<filesDir>/dsh-harmony-data/node-boot.log`（宿主壳日志）
与 `node-stdout.log`（node 自己的输出，端口就是从它里面解析的）。

## 9. 一页速查：我们踩过并已解决的坑

| 现象 | 真因 | 修法 |
|---|---|---|
| `dlopen` 成功但 `dlsym` 全 null | 符号名靠猜 ✗ | 用 `llvm-nm` 读**真实二进制**的导出符号（`_ZN4node5StartEiPPc`），别用合成的对象文件推断 |
| `node::Start` 里 SIGTRAP，`Check failed: 12 == (*__errno_location())` | V8 运行时 `PROT_EXEC` 被 W^X 拒绝 | 启动加 `--jitless` |
| libuv 在 loop init 就崩 | `io_uring_setup` 被 seccomp trap | SIGSYS shim 转成**正好 `-1`** + `UV_USE_IO_URING=0` |
| 启动即 ANR（`APP_INPUT_BLOCK`） | `dlopen`/`node::Start` 跑在 UI 线程 | 开 **detached 线程**做 |
| ArkTS 报 `arkts-no-any-unknown` | 原生模块类型没接上 | `oh-package.json5` 加 `file:` 依赖 + `ohpm install` |
| HAP 里没有 `libs/` | native 产物落在 `build/` | CMake 设 `CMAKE_LIBRARY_OUTPUT_DIRECTORY` → `entry/libs/<abi>/` |
| 载荷 11419 → HAP 11337 | hvigor 排除点文件 | 无害；核对时**查 HAP 而不是磁盘** |
| `llvm-strip` 省不了空间 | Node 官方已 strip | 换别的手段（删插件/改 resfile 存放） |

## 12. ★★★ 已实机跑通：Node.js 运行在鸿蒙上（架构正解）

**证据**（`hdc fport tcp:15577 tcp:5577` 后 `curl http://127.0.0.1:15577/facts`）：
```json
{ "node": "v24.2.0", "platform": "openharmony", "arch": "arm64",
  "execArgv": ["--expose-internals","--jitless","--no-verify-heap"],
  "jitless": true, "exposeInternals": true,
  "native": { "internalModules": true,
              "koffi": "not-loaded(MODULE_NOT_FOUND)",
              "node-pty": "not-loaded(MODULE_NOT_FOUND)",
              "sharp": "not-loaded(MODULE_NOT_FOUND)" } }
```

### 正确的架构链路
```
ArkTS UI
 └─ NAPI libnode_ctl.so
     ├─ detached 线程（UI 线程做 dlopen 会 ANR）
     ├─ SIGSYS shim（io_uring_setup 的 seccomp trap → 正好 -1）
     ├─ 崩溃处理器（backtrace → 文件 + **hilog**）
     ├─ setenv(UV_USE_IO_URING=0)  ← 必须在 libuv 初始化前
     └─ dlopen(libnode.so) → dlsym("_ZN4node5StartEiPPc") → node::Start(argc, argv)
```
**JS 载荷**：`rawfile/` →`resourceManager.getRawFileContentSync()` 读字节 → 写入 `filesDir` → 交给 Node
（✗ `resfile/` 的 fs 访问实测不可达；Node 的 musl 裸 `open()` 也读不到 HAP 内部路径）

### 六条硬约束（违反其一就起不来）
1. `libnode.so` 必须是真共享库（`ET_DYN` **无 `INTERP`**）—— 用 `llvm-readelf -l | grep INTERP` 验空
2. **`libc++_shared.so` 必须一起进 HAP** ✗ 否则 dlopen 失败、ArkTS 侧拿到 `undefined`
3. **`argc` 必须排除 argv 末尾的 `nullptr` 哨兵** ✗ 否则 Node 拿到 NULL 参数，5 ms 段错误
4. JS 载荷走 **rawfile + resourceManager**，不要依赖 `resfile` 路径
5. `--expose-internals --jitless --no-verify-heap` 三个都要；有 `--expose-internals` + 20 行 JS 桩
   就**完全免掉原生 `require-builtin` 插件**
6. **一个进程只能 `node::Start` 一次**（`node.cc:827` 断言）—— 不要做进程内自动重启

### 排障通道（结论：hilog + UI）
- 应用侧日志常不进 hilog dump；**沙箱日志文件连 debug 签名也不让 hdc 读**
  ⇒ native 关键信息**必须同时打 hilog**；把状态/`typeof`/日志尾部**刷到 UI 上**用截图定位
- `ark_disasm modules.abc` 可在本地判断原生导入被编译成了什么（grep `requireNapi`）
- `hdc fport` + `curl` 是最硬的端到端验证手段

## 一、★ 高价值线索：`childProcessManager`（可能解锁两件大事）

**背景**：我曾下结论「鸿蒙一个 bundle 一个进程，app 不能自建进程 ⇒ 进程外看门狗不可能」✗。
**这个结论是错的** ✗ —— 我当时只查了 `module.json` 的 `process` 字段，**没查运行时的 API**。

**正解**（SDK 里确认存在 ✓，`@ohos.app.ability.childProcessManager`）：

```ts
export const enum StartMode { SELF_FORK = 0, ... }
function startChildProcess(srcEntry: string, startMode: StartMode): Promise<number>;              // since 11
function startArkChildProcess(srcEntry: string, args: ChildProcessArgs,
                              options?: ChildProcessOptions): Promise<number>;                   // since 12
function startNativeChildProcess(entryPoint: string, args: ChildProcessArgs,
                                 options?: ChildProcessOptions): Promise<number>;                 // since 13 ★
```

- `srcEntry` 是**相对 `src/main` 的路径**，例如 `./ets/process/DemoProcess.ets`
- 子进程入口是 `ChildProcess` 基类的 `onStart(args?: ChildProcessArgs)`；
  **该函数一返回，子进程就被系统销毁** ⇒ 要常驻就必须在它里面不返回
- `ChildProcessOptions` 支持 `isolationMode` / `isolationUid` ⇒ **可以跑在独立 uid 下** ✓
- 返回的是**子进程 pid** ✓
- 相关声明文件：`ets/api/@ohos.app.ability.{ChildProcess,ChildProcessArgs,ChildProcessOptions,childProcessManager}.d.ts`

**它可能解锁什么**：
1. **把端上 Node 放进子进程** ⇒ 主进程（ArkTS）就能在 Node 崩溃后**重启它** ✓
   （现在 `node::Start` 一进程只能调一次 ✗，崩了只能让用户杀 App 重开 ✗）
2. **进程外看门狗** ⇒ 主进程 / 子进程互相盯着 ✓

**为什么这次没做完**：我第一次尝试时踩了坑 ——
ArkTS 里没有 `process` ✗（要用 `@ohos.process` 的 `pid` ✓）；修好编译之后 **App 却起不来了** ✗。
当时误判为代码问题，回退源码 + 全量重编译都没用 ✗，
最后发现是 **App 的持久化数据坏了**，`bm uninstall` 重装即恢复 ✓（详见 `~/.dsh/AGENTS.md` 第二十二章）。
⇒ **教训：动 ArkTS 之前，先确认"起不来"的排查路径能走通**，否则会把简单问题误判成代码问题。

**下次怎么做（安全三阶段）**：
1. 先只加一个**最小**的 `ChildProcess` 探针（`onStart` 里只打 hilog 的 pid），**只验证"能起子进程"** ✓
2. 再验证"子进程能活多久"（在 `onStart` 里等，看 pid 何时消失）
3. 最后才考虑把 `libnode_ctl.so` 的入口挪进 `startNativeChildProcess`

## 二、UI 自动化的现实边界（能用日志就别点 UI）

本轮实测：**「选择工作区目录」对话框**让我的自动化流程失效 ✗ ——
「点 workspace」+「Back」的老套路对它无效（它是带「取消 / 打开」按钮的系统对话框 ✓）。

**⇒ 更可靠的做法：能用日志验证的，就别点 UI** ✓✓

验证「插件是否加载」（有前两行、无第三行即为成功）：
```powershell
hdc rport tcp:19999 tcp:19999            # 日志通道

#   dsh web: http://127.0.0.1:3080/?token=...

```

**而且端上的这些文件居然可以直接读** ✓（比点 UI 硬得多）：
```powershell
$d = '/data/app/el2/100/base/com.dsh.harmony/haps/entry/files/dsh-harmony-data'
hdc shell ls -la $d/cordis.patch.yml
hdc shell cat  $d/cordis.patch.yml
```
